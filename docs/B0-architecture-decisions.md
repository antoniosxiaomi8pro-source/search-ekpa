## 3. Αποθήκευση: χωρίς βάση δεδομένων

- **Δεν** χρησιμοποιούμε PostgreSQL ή SQLite. Μένουμε στο μοτίβο που λειτουργεί ήδη για τα taxonomies: **αρχεία JSON στο `DATA_DIR`**, αποθήκευση atomic, έλεγχος μορφής, έλεγχος αλλαγών στην κατάταξη, εφαρμογή χωρίς redeploy.
- Τα δεδομένα του ΕΚΠΑ στο `DATA_DIR`:

| Αρχείο | Περιεχόμενο | Πώς αλλάζει |
|---|---|---|
| `programs.json` | Κατάλογος προγραμμάτων | Κουμπί «Έλεγχος καταλόγου» |
| `concepts.json` | Taxonomies / έννοιες | Admin taxonomy (υπάρχει) |
| `lexicon.json` | Λεξικό: stopwords, Greeklish, αντιστοιχίσεις κατηγορίας, κοινού και θέματος | Νέα σελίδα admin |

- Το **typo recovery (G5)** μένει αλγοριθμικό, μέσα στον κώδικα. **Δεν** γίνεται χειροκίνητο λεξικό.
- Διαχείριση των ίδιων των προγραμμάτων (επεξεργασία πεδίων) στο admin: **μόνο αν ζητηθεί**.
- Κάθε αρχείο έχει `schema_version`. Αν αλλάξει η μορφή, ο κώδικας μετατρέπει αυτόματα το παλιό αρχείο στο πρώτο ξεκίνημα, **αφού κρατήσει πρώτα backup**.

## 4. Παράδοση στο IT: πακέτα

- Κάθε αλλαγή κώδικα σημαίνει **νέο πακέτο με ημερομηνία**. Τα πακέτα που έχουν σταλεί **δεν αλλάζουν ποτέ**.
- Ροή: `Local → GitHub → Railway testing → E2E → frozen artifact → πακέτο IT`. Το deploy στο production το κάνει το IT.
- Το πακέτο περιέχει **μόνο κώδικα** και αρχικά δεδομένα. Τα αρχικά δεδομένα χρησιμοποιούνται **μόνο αν το `DATA_DIR` είναι άδειο**. **Ποτέ** δεν αντικαθιστούν δεδομένα του ΕΚΠΑ.
- Νέους όρους που προτείνει η Brandery τους στέλνουμε ως **«Προτάσεις»**: λίστα στο admin με **Αποδοχή / Απόρριψη**. Τίποτα δεν εφαρμόζεται χωρίς τον admin του ΕΚΠΑ.
- Λιγότερα, μεγαλύτερα πακέτα: ένα ανά ολοκληρωμένο βήμα. Εξαίρεση μόνο τα επείγοντα.
- Το πακέτο το φτιάχνει **script** (R0), όχι χειροκίνητα.

## 5. Κατάλογος προγραμμάτων

- **Πηγή 1 (τώρα):** το δημόσιο site `elearningekpa.gr`.
- **Πηγή 2 (όταν δοθεί):** feed ή endpoint του IT. Πρόσβαση θα έχει και ο Αντώνης. Οι προδιαγραφές έχουν σταλεί στον Γιάννη, αναμένεται απάντηση.
- Και οι δύο πηγές βγάζουν τα δεδομένα στην **ίδια μορφή**. Το κουμπί μένει ίδιο και αλλάζει μόνο η πηγή.
- **Κουμπί «Έλεγχος καταλόγου»** στο admin, και στο production και στο Railway:
  - Τρέχει στο παρασκήνιο με μπάρα προόδου (περίπου 10 λεπτά με πηγή το site).
  - Βγάζει λίστα αλλαγών: νέα, αφαιρεμένα, αλλαγή τιμής, τίτλου ή κατηγορίας, αναφορές λεξικού σε προγράμματα που δεν υπάρχουν πια.
  - Υπολογίζει **αυτόματα** τα παράγωγα πεδία (tags, concepts, κατηγορίες, σχετικά προγράμματα).
  - Δείχνει αλλαγές στα αποτελέσματα αναζήτησης, χωριστά: **«αναμενόμενες»** (επειδή μπήκε ή έφυγε πρόγραμμα) και **«άλλες»** (χρειάζονται έγκριση).
  - **Δικλείδα:** αν το αποτέλεσμα είναι ύποπτο (π.χ. αφαιρείται μεγάλο ποσοστό του καταλόγου), η «Εφαρμογή» κλειδώνει.
  - Backup πριν από κάθε εφαρμογή, **επαναφορά με ένα κλικ**.
- **Προγράμματα που δεν δέχονται εγγραφές κρύβονται** από την αναζήτηση (suggestions, σελίδα αποτελεσμάτων, σχετικά προγράμματα) και ξαναεμφανίζονται όταν ανοίξουν.
  - Κάθε πρόγραμμα έχει πεδίο `status` (`active` / `inactive`) και `status_source` (από πού προέκυψε: site, feed ή χειροκίνητα).
  - Το φιλτράρισμα γίνεται **πριν** τη μηχανή αναζήτησης (στα δεδομένα). Το προστατευμένο search core δεν αλλάζει.
  - Μέχρι το feed, η κατάσταση βγαίνει από τα στοιχεία του site. Όταν έρθει το feed, γίνεται οριστικά από εκεί.
  - Κανόνας «κατά γράμμα» (απόφαση 01/10): κρύβεται και πρόγραμμα που είναι στη λίστα του κύκλου αλλά η σελίδα του λέει «Το πρόγραμμα δεν είναι διαθέσιμο» (έληξε η προθεσμία αιτήσεων). Ο κύκλος δεν σταματά ποτέ, ο επόμενος ανοίγει αμέσως, άρα δεν μένει κενή αναζήτηση. Αν ένας έλεγχος πέσει στο διάστημα που οι σελίδες δεν έχουν ενημερωθεί ακόμα, η δικλείδα του 15% μπλοκάρει την εφαρμογή και μένει η προηγούμενη κατάσταση.
  - Καταγράφεται και η `application_deadline` κάθε προγράμματος.
  - **Νέα προγράμματα** που εμφανίζονται στον κύκλο **προστίθενται** στον κατάλογο (όχι μόνο αναφορά), με όλα τα πεδία που χρειάζεται η αναζήτηση, ώστε να κατατάσσονται όπως τα υπάρχοντα. Με τους ίδιους κανόνες **συμπληρώνονται και τα κενά** των υπαρχόντων (id, κατηγορία, περιγραφή, έννοιες/tags, σχετικά). **Μόνο κενά πεδία, τίποτα υπάρχον δεν αλλάζει.** Κάθε εφαρμογή περνά από `npm run ranking:diff` και έγκριση. Κανόνες: `server/program-enrich.js`, LEDGER 01/10.
  - Τα κρυμμένα προγράμματα **δεν διαγράφονται**: μένουν στο `programs.json` με `inactive`, ώστε να ξαναενεργοποιούνται χωρίς απώλεια (tags, ιστορικό κλικ).
- **Εβδομαδιαία ελαφριά υπενθύμιση:** σύντομος έλεγχος της λίστας του site. Αν υπάρχει διαφορά, μήνυμα στο admin «προτείνεται έλεγχος».

## 6. Δεδομένα χρήσης: GA4

- Πηγή δεδομένων production για τη Brandery: **GA4 `G-ZL8304SEHG`**. Τα analytics του server του IT τα βλέπει το ΕΚΠΑ στο admin.
- Προϋπόθεση: [MANUAL-GA4-Smart-Finder.md](MANUAL-GA4-Smart-Finder.md) (custom dimensions και διατήρηση 14 μηνών).
- R4, αρχικά: export CSV από το GA4, αναφορά, εγκεκριμένες προτάσεις στις **«Προτάσεις»** του επόμενου πακέτου. Αργότερα, αν αξίζει, GA4 Data API.
- Μελλοντική μικρή αλλαγή στο widget: πλήθος αποτελεσμάτων στο `search`, events για Enter, «Εμφάνιση περισσότερων» και ταξινόμηση.

## 7. Κύκλος εργασιών (ανά κύκλο σπουδών, περίπου κάθε 3 μήνες)

1. **Έλεγχος καταλόγου** (κουμπί), στην αρχή του νέου κύκλου (φρέσκες τιμές για την ταξινόμηση).
2. **Αναφορά GA4** για τον κύκλο που τελείωσε.
3. **Προτάσεις λεξικού**, που τις αποδέχεται ή τις απορρίπτει το ΕΚΠΑ.
4. **Πακέτο IT**, μόνο αν υπάρχει αλλαγή κώδικα.

## 10. Ευρήματα από το δημόσιο site (έρευνα 01/10/2026, και στα 702 προγράμματα)

**α) Η σελίδα `https://elearningekpa.gr/course-schedule` («Τρέχων Κύκλος») είναι η λίστα των ενεργών προγραμμάτων.**
Περιέχει 695 προγράμματα, και η κατανομή ταιριάζει ακριβώς:

| | Πλήθος | Τι δείχνει η σελίδα του προγράμματος |
|---|---|---|
| Στη λίστα «Τρέχων Κύκλος» | **695** | «Έναρξη Μαθημάτων 19/10/2026 · Κάνε Αίτηση», `startDate` στο JSON-LD |
| Εκτός λίστας, η σελίδα υπάρχει | **5** | «Το πρόγραμμα δεν είναι διαθέσιμο.», χωρίς `startDate` (για το CCNA δεν υπάρχει το μήνυμα, μόνο λείπει το `startDate`) |
| Εκτός λίστας, η σελίδα δεν υπάρχει (404) | **2** | Αφαιρέθηκαν από το site |
| **Σύνολο** | **702** | |

Συνέπειες:
- **Κριτήριο κατάστασης μέχρι το feed:** `active` = υπάρχει στο «Τρέχων Κύκλος». Επιβεβαίωση από τη σελίδα του προγράμματος (`startDate`, ή το μήνυμα «δεν είναι διαθέσιμο»).
- **Εβδομαδιαία υπενθύμιση:** ένα μόνο αίτημα (η σελίδα «Τρέχων Κύκλος», περίπου 1MB). Αν η λίστα διαφέρει από τον κατάλογο, μήνυμα στο admin.
- Νέα προγράμματα του κύκλου εμφανίζονται κι αυτά στη λίστα, άρα εντοπίζονται με τον ίδιο τρόπο.

**β) Κάθε σελίδα προγράμματος έχει structured data (JSON-LD `Course`)** με `offers.price`, `hasCourseInstance.startDate`, `teaches` (ύλη), διδάσκοντα, τύπο πιστοποιητικού.
- **Τιμή υπάρχει και στα 699 προγράμματα που απάντησαν.** Από τα **262 χωρίς τιμή** στα δεδομένα μας, συμπληρώνονται **και τα 262**.
- Η τιμή του JSON-LD είναι **η τρέχουσα με έκπτωση**: σε όλα τα 387 που έχουμε ήδη τιμή είναι 3,6–6,7% χαμηλότερη (διάμεσος −5%, π.χ. 950 → 900). Αντιστοιχεί στην ειδική έκπτωση του κύκλου. → Ανοιχτό θέμα 5.
- Το `teaches` (λίστα ενοτήτων) είναι πιθανή μελλοντική πηγή για καλύτερη αναζήτηση. **Δεν** μπαίνει στο search core χωρίς δική του απόφαση και regression parity.

**γ) Πρακτικό:** με γρήγορα διαδοχικά αιτήματα το site απαντά **403** (περιορισμός ρυθμού). Με ένα αίτημα κάθε 2 δευτερόλεπτα δεν εμφανίστηκε κανένα 403. Ο πλήρης έλεγχος καταλόγου πρέπει να τηρεί αυτό τον ρυθμό (περίπου 25 λεπτά για 700 σελίδες στο παρασκήνιο). Ο έλεγχος «Τρέχων Κύκλος» είναι ένα αίτημα.
